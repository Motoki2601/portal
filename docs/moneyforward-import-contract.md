# Money Forward ME CSV：取込契約案

関連: #13 / #11 / #12。MVP仕様: household-data-mvp.md
状態: 提供サンプルの形式確認済み。Amazon注文明細との突合は未検証。
この文書には利用者の実取引、集計結果、口座名、元IDを記載しない。

## 確認した形式
UTF-8 BOM付きCSV。ヘッダーは以下の10列。
計算対象 / 日付 / 内容 / 金額（円） / 保有金融機関 / 大項目 / 中項目 / メモ / 振替 / ID

金額は符号付き整数、日付はYYYY/MM/DD、計算対象と振替は0/1。
提供サンプルでは形式変換可能な値を確認したが、他の出力でも必ず同じとは仮定しない。
商品名・数量・ASIN・注文番号の専用列はない。
内容が加盟店名だけの場合、商品や在庫を生成しない。

## 正規化先: financial_transactions（論理モデル案）
| 元列 | 正規化項目 | 変換・意味 |
|---|---|---|
| ID | source_record_id | 文字列のまま保持 |
| 計算対象 | included_in_budget | 0/1をbooleanへ。商品判定に使わない |
| 日付 | source_date | 日付として保存。注文/入荷日と同一視しない |
| 内容 | description_raw | 原文を保持 |
| 内容 | description_normalized | NFKC、前後空白除去、英字大小統一。検索/候補検出用 |
| 金額（円） | amount_jpy | 符号付き整数。負が出金、正が入金。返金/給与等は別途分類 |
| 保有金融機関 | source_account_ref | 個人データとして保存。公開コードに埋め込まない |
| 大項目/中項目 | category_major/minor | 元の分類。購入商品や容量の根拠にしない |
| メモ | memo_raw | 空欄可 |
| 振替 | is_transfer | 0/1をbooleanへ。元データと家計集計上の意味を保存 |

共通項目: user_id、source_system、import_id、row_number、parser_version、recorded_at。
商品・注文とのリンクは確定できた場合に別途作成する。

## 支出と商品購入を分ける
- financial_transactions: お金の動き/家計簿の明細。
- purchase_orders / purchase_lines: 商品、数量、価格、注文番号など。
- transaction_order_links: 確認済みの対応。分割請求、複数注文の合算、返金を考慮して多対多を許す。
- inventory_events: 入荷、開封、使い切り、残量確認など。

カード明細の加盟店がAmazonでも、物品・デジタル商品・会費・Amazon Pay等を区別できない場合がある。
加盟店検索は「商品情報を補う候補」であり、購入商品の確定ではない。
金額と日付だけの一致は突合候補に留める。

## 再取込・更新
同じ利用者/ソース/接続口座のsource_record_idを同一性の基準にする。
別の接続口座でIDが一意かは保証未確認のため、IDだけを全体のキーにしない。
同一ID・同一内容はno-op、同一ID・変更ありは更新履歴を残して再取込する。
元IDがない形式ではファイルハッシュと行番号で同一ファイル再送を防ぐ。
別ファイルとの重複は別途候補検出して確認する。
取込エラーでは行番号・列・理由を表示する。成功/失敗行数を返す。

## 今回の取込で決めた境界
- MF CSVはまずfinancial_transactionsへ取り込む。
- 商品情報のない行からproduct / purchase_line / inventory_eventを自動作成しない。
- 消費速度、保有数量、入荷日をカード明細から推定して確定値にしない。
- 表記正規化は派生列で行い、原文は維持する。
- 家計集計では計算対象/振替を尊重する。支出総額の分析は今回の目的に含めない。

## 次に必要な検証
Amazon注文履歴の10〜20明細程度で、商品名・注文日・注文番号・数量・商品金額・商品URL/識別子の有無を確認する。
数量等が欠けていたら本人確認または別の注文資料で補う。
提供された形式を調べてからパーサーを決め、特定のエクスポート形式を仮定しない。
最低1件の複数商品注文/数量違いがあるとパック数と注文数量の違いを確認しやすい。
MF通販連携からの商品明細は別形式が提供された場合に検証する。現在のカード由来CSVでは代替できない。

## 実装時に必要な確認（架空fixtureのみ）
1. UTF-8 BOM、日本語、全角英字の加盟店名。
2. 符号付き金額、空のメモ、0/1フラグ。
3. 同一ファイル再取込で件数が増えない。
4. 同一IDでカテゴリやメモが変わった再取込。
5. 日付不正、金額不正、ID欠損、不足ヘッダー、列順変更。
6. 商品情報がない明細で商品/在庫が増えない。
7. 他ユーザー/他口座のIDと衝突しない。
